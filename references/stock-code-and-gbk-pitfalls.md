# 股票代码记忆与 QBK 编码陷阱（2026-08-26 白银有色事故）

## 事故A：股票代码记忆错误 → 腾讯API静默返回"另一只股票"

**经过**：主人问"白银有色(601212)怎么处理"，小奶茉凭记忆填了 `600586` 去查。腾讯 `qt.gtimg.cn/q=sh600586` **不报错**，直接返回名称为"金晶科技"的完整行情——走错了票，后续成本/浮亏全部算错。

**根因**：A股代码纯靠记忆，无严格规律。填错后 API 验证不出错，静默喂给错误数据。

**强制规则**：
1. 查任何个股行情，拉取后先比对 `parts[1]`（股票名）与用户所问是否一致，不一致立即换码。
2. 不凭印象填代码。用户只报名称时，先确认代码再发请求。
3. 分析成本/浮亏前，先打印名称确认代码正确。

**常见易混代码**：
| 名称 | 正确代码 | 曾误填 |
|------|---------|--------|
| 白银有色 | 601212 | 600586（实为金晶科技）|
| 微芯生物 | 688321 | 普冉股份（2026-07-24 早盘快报）|

## 事故B：腾讯行情API中文名乱码 → 必须 GBK 解码

**经过**：本会话最初用 `decode('utf-8', errors='replace')` 拉 `qt.gtimg.cn`，得到 `ʵ` 这类乱码，股票名无法辨认。

**根因**：腾讯行情返回的中文字段是 **GBK 编码**。

**正确做法**：
```python
raw = urllib.request.urlopen(req, context=ctx).read()
text = raw.decode('gbk', errors='replace')
```
- `parts[1]` 股票名、板块名等**中文名称字段**必须是 GBK。
- K 线/价格的数字字段不受影响。
- 判断：名称乱码是编码问题，不是 API 或网络问题。
