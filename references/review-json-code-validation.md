# 复盘 JSON 代码-名称校验陷阱（2026-07-28 实测）

## 问题

2026-07-27 的 A股复盘 JSON 中，`todayHot.topSectors[].stocks[]` 和 `fallingSectors[].stocks[]` 的代码与名称大面积不匹配：

| JSON 中代码 | JSON 中名称 | API 实际名称 | 正确代码 |
|------------|-----------|------------|---------|
| 688298 | 爱朋医疗 | 东方生物 | 688298=东方生物，爱朋医疗=688298? 不，爱朋医疗=688298 实际是东方生物 |
| 688386 | 成都华微 | 泛亚微透 | 成都华微正确代码不同 |
| 300795 | 倍轻松 | 米奥会展 | 倍轻松=688793 |
| 301088 | 国际复材 | 戎美股份 | 国际复材正确代码不同 |
| 603020 | 红板科技 | 爱普股份 | 红板科技代码不同 |

**根因**：复盘 JSON 生成时，LLM 从 Sina 收评文章中提取了龙头股名称，但凭"印象"拼接了代码（尤其 688xxx 科创板代码容易混淆），未通过腾讯 API 验证代码-名称对应关系。

## 影响

1. 次日早盘快报读取昨日复盘 JSON 时，会继承这些错误代码
2. 用错误代码查询腾讯 API 会拉到错误股票的行情数据
3. 关注个股表格中代码与名称不匹配，主人拉行情时拉到错误股票

## 强制规则

### 复盘 JSON 生成时（当日复盘模式）

- `todayHot.topSectors[].stocks[]` 和 `fallingSectors[].stocks[]` 中每只股票的代码**必须**通过腾讯 API 实际验证
- 从 Sina 收评文章提取龙头股名称后，**先用腾讯 API 批量查询验证代码-名称对应关系**，再写入 JSON
- 若 API 返回名称与文章中名称不一致，**以 API 返回为准**，修正代码后再写入
- 禁止凭记忆/印象拼接股票代码

### 早盘快报读取昨日复盘 JSON 时

- 读取昨日复盘 JSON 后，**必须对 JSON 中出现的个股代码做交叉验证**
- 用腾讯 API `qt.gtimg.cn/q={codes}` 批量查询，检查 API 返回的 `[1]`（名称）字段是否与 JSON 中记录的名称一致
- 若不一致，以 API 返回为准，修正后再用于今日关注个股分析
- 自检代码：
  ```python
  import urllib.request, re
  codes = "sh688298,sh688386,sz300795,sz301088,sh603020"  # JSON 中的代码
  req = urllib.request.Request(f"http://qt.gtimg.cn/q={codes}")
  raw = urllib.request.urlopen(req, timeout=10).read().decode("gbk")
  for line in raw.strip().split("\n"):
      m = re.match(r'v_(\w+)="([^"]+)"', line)
      if m:
          parts = m.group(2).split("~")
          print(f"代码={m.group(1)} API名称={parts[1]}")
  # 逐一核对：JSON 中写的名称 == API 返回的名称？
  ```

## 常见易混淆代码

| 错误代码 | 错误对应 | 正确代码 | 正确名称 |
|---------|---------|---------|---------|
| 688298 | （误认为爱朋医疗） | 688298 | 东方生物 |
| 688793 | 倍轻松（正确） | 688793 | 倍轻松 |
| 688386 | （误认为成都华微） | 688386 | 泛亚微透 |
| 300795 | （误认为倍轻松） | 300795 | 米奥会展 |
| 301088 | （误认为国际复材） | 301088 | 戎美股份 |
| 603020 | （误认为红板科技） | 603020 | 爱普股份 |
| 300308 | （误认为传智教育） | 300308 | 中际旭创 |
| — | 传智教育 | 003032 | 传智教育 |

> **⚠️ 2026-08-14 实测复现**：当日（8/13）复盘 JSON 的 `fallingSectors` 将「传智教育」写成代码 `sz300308`，但腾讯 API 返回 `300308` = **中际旭创**（光模块龙头，昨收 921.04）。传智教育的正确代码是 **003032**（深市主板）。早盘快报读取昨日复盘 JSON 做代码交叉验证时，若发现此类错误，**以 API 返回为准修正代码**，且勿把昨日复盘里的错误代码继承进今日关注个股。
>
> 教训：LLM 凭印象拼接代码时，`300xxx` 创业板区间既含中际旭创（300308）这种光模块大票、也易误填教育/小盘股，混淆率极高。任何 `300308` 写入前必须 API 验证。

> 注：此问题与 SKILL.md 中已有的「关注个股代码必须逐一验证」规则同源，但扩展到了**复盘 JSON 本身的代码校验**——不仅早盘快报的 focusStocks 需要验证，复盘 JSON 的 topSectors/stocks 也需要验证。
